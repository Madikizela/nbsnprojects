# Render Deployment Guide — NBSN Projects

This guide walks you through deploying the full stack (PostgreSQL + .NET 9 backend + React frontend) on [Render](https://dashboard.render.com).

---

## What Gets Deployed

| Resource | Render Type | Docker context |
|---|---|---|
| `nbsn-postgres` | PostgreSQL database | — |
| `nbsn-backend` | Web service (Docker) | `backend/Dockerfile.production` |
| `nbsn-frontend` | Web service (Docker) | `frontend/Dockerfile.production` |

Migrations run automatically on every backend deploy via `Database.MigrateAsync()` in `Program.cs`.

---

## Prerequisites

- A [Render account](https://dashboard.render.com/register) (free tier works for starter)
- This repository pushed to GitHub or GitLab (Render pulls directly from Git)
- Your SMTP credentials (Gmail app password, or any SMTP provider)
- Optional: WhatsApp Business API credentials (Meta Cloud API)

---

## Step 1 — Connect Your Repository

1. Log in to [dashboard.render.com](https://dashboard.render.com).
2. Click **New → Blueprint**.
3. Connect your GitHub/GitLab account if prompted, then select this repository.
4. Render detects `render.yaml` automatically and shows a preview of the three resources.
5. Click **Apply** to start provisioning.

> The first build takes ~5–10 minutes. The .NET SDK image is large; subsequent deploys are faster due to Docker layer caching.

---

## Step 2 — Set the Secret Environment Variables

Several variables are marked `sync: false` in `render.yaml`, meaning Render will not set them automatically. You must add them manually **before** clicking Apply (or immediately after, then trigger a redeploy).

Go to each service → **Environment** tab and add:

### Backend (`nbsn-backend`)

| Variable | Value |
|---|---|
| `DEFAULT_ADMIN_PASSWORD` | A strong password, e.g. `Admin@123!System` |
| `SMTP_USER` | Your Gmail address, e.g. `yourname@gmail.com` |
| `SMTP_PASS` | Your Gmail **App Password** (16-char, no spaces) |
| `FROM_EMAIL` | Same as `SMTP_USER` |
| `WHATSAPP_PHONE_NUMBER_ID` | From Meta Developer Console (optional) |
| `WHATSAPP_ACCESS_TOKEN` | Permanent token from Meta (optional) |
| `WHATSAPP_BUSINESS_ACCOUNT_ID` | From Meta Developer Console (optional) |
| `LEARNER_PORTAL_URL` | Set **after** frontend is live, e.g. `https://nbsn-frontend.onrender.com/learner` |

> `JWT_SECRET` and `ENCRYPTION_DATA_KEY` are auto-generated by Render (`generateValue: true`) — you don't need to set those.

### Frontend (`nbsn-frontend`)

| Variable | Value |
|---|---|
| `VITE_API_URL` | Your backend URL, e.g. `https://nbsn-backend.onrender.com` |

> `VITE_API_URL` is a **build-time** variable. It gets baked into the JavaScript bundle. Every time you change it you need to trigger a manual redeploy of the frontend.

---

## Step 3 — Confirm the Deploy Order

Render respects the resource order in `render.yaml`:

1. **Database** (`nbsn-postgres`) — provisioned first
2. **Backend** (`nbsn-backend`) — starts after DB is ready; `DATABASE_URL` is auto-injected
3. **Frontend** (`nbsn-frontend`) — starts in parallel with the backend

The backend startup logs will show:
```
⏳ Applying pending EF Core migrations...
✅ EF Core migrations applied successfully
✅ Database connection established successfully
```

If you see a migration error on the first deploy, it usually means the database wasn't ready yet. Use **Manual Deploy → Deploy latest commit** on the backend service to retry.

---

## Step 4 — Verify the Services

Once all three services show **Live** status:

### Backend health check
```
GET https://nbsn-backend.onrender.com/api/health
```
*(or any endpoint — the app has no dedicated `/health` route yet, so try `GET /` which returns 404 but confirms the server is running)*

### Frontend
Open `https://nbsn-frontend.onrender.com` in your browser. You should see the login page.

### Login with the default admin account
- **Email:** `admin@system.local`
- **Password:** the value you set for `DEFAULT_ADMIN_PASSWORD`

---

## Step 5 — Update `LEARNER_PORTAL_URL`

After confirming the frontend is live:

1. Go to `nbsn-backend` → **Environment**.
2. Set `LEARNER_PORTAL_URL` to `https://nbsn-frontend.onrender.com/learner`.
3. Click **Save Changes** — Render will automatically redeploy the backend.

---

## Custom Domains (Optional)

1. Go to a service → **Settings → Custom Domains**.
2. Add your domain (e.g. `api.yourdomain.com` for backend, `app.yourdomain.com` for frontend).
3. Add the CNAME record shown by Render to your DNS provider.
4. After the domain is verified, update `VITE_API_URL` on the frontend to the new backend domain and redeploy.

---

## Redeploying After Code Changes

Render auto-deploys on every push to the `main` branch by default.

To trigger a manual redeploy: service → **Manual Deploy → Deploy latest commit**.

> **Frontend rebuild reminder:** if you change the backend URL, update `VITE_API_URL` and redeploy the frontend — the old URL is baked into the bundle.

---

## Important Limitations on the Free/Starter Plan

| Limitation | Detail |
|---|---|
| **Ephemeral filesystem** | Files uploaded to `/app/uploads` (profile photos, documents) are wiped on every redeploy. For persistent file storage, integrate AWS S3, Cloudinary, or similar and update `DocumentUploadService`. |
| **Cold starts** | Free-tier web services spin down after 15 minutes of inactivity and take ~30 seconds to wake up. Upgrade to **Starter** ($7/month) for always-on. |
| **Free PostgreSQL expiry** | Free PostgreSQL databases expire after 90 days. Use the **Starter** plan ($7/month) for persistent databases. |

## Troubleshooting

### Build fails: `SkiaSharp native library not found`
The `Dockerfile.production` already installs `fontconfig` and `ttf-dejavu` via `apk`. If the error persists, ensure you are using `Dockerfile.production` (not `Dockerfile`) as the Dockerfile path in the service settings.

### `DATABASE_URL not set` on first deploy
The database may still be provisioning when the backend first starts. Wait a minute and click **Manual Deploy → Deploy latest commit** on the backend service.

### Frontend shows a blank page or API errors
1. Check that `VITE_API_URL` is set correctly on the frontend service.
2. Make sure the value does **not** have a trailing slash: `https://nbsn-backend.onrender.com` ✓, `https://nbsn-backend.onrender.com/` ✗.
3. Redeploy the frontend after correcting the variable.

### CORS errors in browser
The backend uses `AllowAnyOrigin()` so CORS should not be an issue. If you see CORS errors, confirm the frontend is calling the correct backend URL and not `localhost`.

### Migrations failed / tables missing
SSH is not available on Render's free tier. The safest fix is to ensure `Database.MigrateAsync()` runs on startup (already done in `Program.cs`). Trigger a backend redeploy and watch the logs.

## Environment Variable Reference

Full list of all variables the backend reads:

| Variable | Required | Auto-set? | Description |
|---|---|---|---|
| `DATABASE_URL` | Yes | By Render (from DB resource) | Full PostgreSQL connection URL |
| `ASPNETCORE_ENVIRONMENT` | Yes | In render.yaml | Set to `Production` |
| `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT` | Yes | In render.yaml | Must be `false` for PDF generation |
| `JWT_SECRET` | Yes | Generated by Render | Min 32 chars |
| `JWT_ISSUER` | Yes | In render.yaml | Token issuer claim |
| `JWT_AUDIENCE` | Yes | In render.yaml | Token audience claim |
| `JWT_EXPIRY_MINUTES` | No | In render.yaml | Default `60` |
| `ENCRYPTION_DATA_KEY` | Yes | Generated by Render | AES encryption key |
| `DEFAULT_ADMIN_EMAIL` | No | In render.yaml | Seed admin email |
| `DEFAULT_ADMIN_PASSWORD` | Yes | **Manual** | Seed admin password |
| `SMTP_HOST` | No | In render.yaml | Default `smtp.gmail.com` |
| `SMTP_PORT` | No | In render.yaml | Default `587` |
| `SMTP_USER` | Yes | **Manual** | SMTP username |
| `SMTP_PASS` | Yes | **Manual** | SMTP password / app password |
| `FROM_EMAIL` | Yes | **Manual** | Sender address |
| `FROM_NAME` | No | In render.yaml | Default `NBSN Team` |
| `WHATSAPP_PHONE_NUMBER_ID` | No | **Manual** | Meta Cloud API |
| `WHATSAPP_ACCESS_TOKEN` | No | **Manual** | Meta Cloud API |
| `WHATSAPP_BUSINESS_ACCOUNT_ID` | No | **Manual** | Meta Cloud API |
| `LEARNER_PORTAL_URL` | No | **Manual** | Sent in welcome messages |
| `PORT` | Yes | Auto-injected by Render | Kestrel listen port |
